# 溢价 bps 开平仓策略

在网页配置中选择「溢价 bps 开平仓」，或 YAML 设置 `strategy.mode: bps`。不指定时继续使用旧套利阈值策略；保存配置不会自动启动任务。

这里的 bps 是 `(主腿中间价 / 对冲腿中间价 - 1) × 10000`，不是滑点或净收益。`long_primary` 在溢价低于或等于开仓点位时买主腿、卖对冲腿，回升到或超过平仓点位时成对平仓；`short_primary` 相反，在高位卖主腿、低位成对平仓。实时触发还需满足行情新鲜、订单预算、仓位限制与配置的信号持续时间。

## 自动点位

```yaml
strategy:
  mode: bps
bps:
  levels: rolling
  history_mode: records
  direction: long_primary
  window_minutes: 120
  min_valid_minutes: 30
  entry_percentile: 10
  exit_percentile: 75
  add_interval_sec: 60
  max_position_usd: 1000
```

参数为可修改的示例。默认 `history_mode: records`，每分钟从 YAML `recorder.csv` 中取最新 N 条有效分钟收盘溢价，N 沿用 `window_minutes` 字段，默认 120。允许记录不连续、跨时段，也允许使用本次启动前采集的历史。已有历史超过 120 条就直接用最新 120 条，不必重新采集或等待 120 分钟。

每条须至少 10 次有效采样；同一分钟的有效重复记录只计一次，未完成分钟、未来记录和无效值不参与计算。`min_valid_minutes` 默认 30，实际最低数量为 `min(N, min_valid_minutes)`；设置为 120 就要求 120 条有效历史，但不要求连续。旧版 `min_coverage_pct` 仅为兼容保留，不限制点位计算。

开仓点位取有效记录的第 10 分位数，平仓点位取第 75 分位数；这些分位数可修改。有效记录不足或点位重合时不开新仓。读取在后台线程进行，记录尾部不足时扩大读取范围，不在盘口回调中扫描 CSV。页面显示最新历史参考范围和最后一条记录距今多久；历史可能跨越较长时间，点位不一定适合当前行情。已有持仓继续使用开仓时锁定的点位，后续更新供下一轮参考。

如需保留严格时间窗口，可显式设置 `history_mode: time`：只读取最近 N 分钟时间范围内的有效记录，允许缺口，但不使用窗口外数据补足数量。两种方式均直接复用已有 CSV，重启不清除历史、不重设采集起点，也不要求本次进程重新采集。

CSV 旁的 `.source.json` 记录主腿、对冲腿、市场名称及可用历史起点。没有来源记录的旧 CSV，以及上一版仅记录升级时间的来源记录，会按 YAML 指定路径复用历史，日志提示 `CSV legacy history reused`。这一兼容操作假定旧历史与当前 YAML 的交易所、市场及主/对冲腿方向一致；旧格式无法验证这一点，曾混用路径或对调主腿的历史应先分开存放。升级后的来源记录使用 version 2；此后已记录的交易所/市场或腿方向变化会保留新起点，不混用变化前的数据，也不删除原 CSV。来源记录损坏时拒绝使用，不自动猜测。

第一批成交后，本轮开仓点位和平仓点位固定。之后滚动计算的点位留给下一轮；允许加仓时仍按本轮点位判断。不再限制开仓批次数量，旧 YAML 的 `max_entries` 为兼容保留读取但不再生效；`max_position_usd` 是每条腿的总持仓上限，同时受原有两条腿各自的仓位上限和单笔下单上限约束。

## 手动点位

```yaml
strategy:
  mode: bps
bps:
  levels: manual
  direction: long_primary
  entry_bps: -9
  exit_bps: -6
  max_position_usd: 1000
```

此时不使用滚动分位数。低位策略必须开仓点位小于平仓点位；高位策略必须开仓点位大于平仓点位。

## 成交和成本

开仓遵循现有主腿成交方式。主腿挂单时，仅将已确认成交量在对冲腿吃单对冲；未成交不发送对冲订单。

默认 `execution.maker_cancel_policy: best_price`：先检查本轮 BPS 开仓条件和双腿可交易状态，不满足就立即请求撤单；满足后，买单在买一、卖单在卖一（或报价优于最后公开最优价）持续保留，不设总等待上限。连续离开最优价达到 `execution.maker_reprice_delay_sec`（默认 0.3 秒）才撤单；期间回到最优价会重置确认计时。原阈值策略也先检查自身有效门槛，再判断最优价。信号、对冲深度、行情、订单预算或人工停止等取消条件优先于队列位置，不受离开最优价确认时间影响。

撤单后先确认旧单终态并处理最后新增成交，才释放订单锁并重新评估下一单，不在旧单结果未知时重挂。主腿价格档位不代表精确排队名次，仍在卖一/买一也不保证成交。长时间保留时 Arcus 每 5 秒主动核验订单状态，查询不撤单、不重置排队；WS 与主动查询都无法确认时仍按原保护处理。

如需保留原来的固定超时撤单，可显式设置 `execution.maker_cancel_policy: timeout`，此时 `maker_timeout_sec` 控制最长等待，范围 (0, 60] 秒。最优价模式忽略此总等待时间；网页会隐藏该输入框并展示当前规则。升级时未指定策略的 maker 配置默认采用最优价保留模式。

触发平仓后使用两边 reduce-only 吃单，遵循原有滑点保护和单笔上限；部分成交后继续平剩余仓位，即使溢价随后退回，也不改为反向加仓。小于交易所最小规模但仍超过数量精度的残余仓位会暂停并要求核对；净敞口容差不会把仍可辨认的配对持仓当作空仓。

开平仓只按配置的溢价点位判断，已移除预计净收益计算及成本拦截。手续费、盘口价差和滑点不会改变 bps 开仓点位，但仍影响实际收益。`execution.leg_slippage_bps` 和 `hedge_slippage_bps` 继续作为真实订单的价格保护；不因取消估算而扩大滑点容忍。旧 YAML 的 `bps.cost_buffer_bps` 为兼容保留解析，但不再生效，网页已移除该字段。

该策略没有额外止损或强制最长持仓时间；溢价没有回到平仓点位时继续持仓。停止/暂停程序不会自动平仓。每天 8 点的旧三个套利阈值更新会跳过 bps 策略，不会替换这些点位或重启其持仓周期。

## 重启和日志

日志显示 `[BPS LEVELS]`（来源、窗口及点位）、`[BPS bps_open]`、`[BPS bps_close]`，交易记录的方向带 `bps_open:` 或 `bps_close:`。网页监控摘要显示当前点位、批次和等待/拦截原因。

网页「交易信号」同时支持 bps 策略与套利阈值策略，仅展示状态，不参与订单判断。可成交溢价按卖腿最优报价除以买腿最优报价计算；挂单开仓使用主腿买一/卖一挂单报价，平仓始终使用吃单报价。它不代表整笔订单的实际成交溢价。

bps 模式另列「触发指标」，使用双腿中间价溢价，门槛为本轮开仓/平仓点位；持仓后显示锁定点位。`≤` 条件的 gap 为「门槛 − 触发指标」，`≥` 条件的 gap 为「触发指标 − 门槛」，非负表示达到点位。尚未持仓时平仓行仅作参考。阈值模式的触发指标就是可成交溢价，门槛包含方向阈值、配置手续费与仓位附加值，gap 为可成交溢价减门槛。两种模式均不把 gap 当作净利润，达到点位也不意味着盘口深度、仓位限制等其他交易条件已经满足。

`logging.file` 对应目录中保存 `.bps-state.json`，包括本轮固定点位、批次和最后已确认的仓位。正常重启只有在交易所仓位与记录一致、市场和账户一致时才恢复。没有归属记录的旧仓位、未完成订单或链上仓位变化会拒绝启动或暂停，不猜测仓位归属，不自动反向平掉旧仓位。

若上一轮留下 `pending=true`，启动时会先验证状态属于当前账户和交易对，再直接查询两边对应市场的未成交订单（包括条件单）及实时持仓。间隔 5 秒复查，两次均无挂单且持仓归零才自动解除旧状态。原文件归档为 `*.bps-state.json.recovered-<时间戳>.bak`，分钟行情和成交 CSV 保留；不会猜测手动平仓的成交价或补算旧轮盈亏。净收益模式从核验完成后重新计冷却时间。

任何一边仍有挂单或持仓、查询失败、回包缺字段、账户不匹配，都会保留 `pending` 并拒绝启动。核验只读取账户，不会代为撤单或平仓。日志中的 `[BPS RECOVERY]` 会显示核验进度和结果，无须手工删除状态文件。
