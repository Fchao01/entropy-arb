# 溢价 bps 开平仓策略

在网页配置中选择「溢价 bps 开平仓」，或 YAML 设置 `strategy.mode: bps`。不指定时继续使用旧套利阈值策略；保存配置不会自动启动任务。

这里的 bps 是 `(主腿中间价 / 对冲腿中间价 - 1) × 10000`，不是滑点或净收益。`long_primary` 在溢价低于或等于开仓点位时买主腿、卖对冲腿，回升到或超过平仓点位时成对平仓；`short_primary` 相反，在高位卖主腿、低位成对平仓。实时触发还需满足行情新鲜、订单预算、仓位限制与配置的信号持续时间。

## 自动点位

```yaml
strategy:
  mode: bps
bps:
  levels: rolling
  direction: long_primary
  window_minutes: 120
  entry_percentile: 10
  exit_percentile: 75
  max_entries: 1
  add_interval_sec: 60
  max_position_usd: 1000
  cost_buffer_bps: 0
```

参数为可修改的示例。滚动窗口每分钟更新，读取 YAML `recorder.csv` 展开的路径，要求最近 N 个连续已完成分钟均有有效记录，每条至少 10 次有效采样。开仓点位取第 10 分位数，平仓点位取第 75 分位数；这些分位数也可修改。数据不足、有缺口或窗口波动不足时不开新仓，不填充数据。读取在后台线程进行，不在盘口回调中扫描文件。

CSV 旁的 `.source.json` 记录主腿、对冲腿、市场名称及开始采集时间。旧 CSV 没有来源记录、换了交易所或对调主腿时，需要重新积累 N 个完整分钟，避免把反向溢价或其他市场历史作为信号。CSV 仍保存在 YAML 指定的原路径；不删除旧 CSV。网页图表可能继续显示旧历史，新策略仅使用来源已确认的数据。

第一批成交后，本轮开仓点位和平仓点位固定。之后滚动计算的点位留给下一轮；允许加仓时仍按本轮点位判断。`max_entries` 包括首次开仓，只有实际增加了配对持仓才占用批次；`max_position_usd` 是每条腿的总持仓上限，同时受原有两条腿各自的仓位上限和单笔下单上限约束。

## 手动点位

```yaml
strategy:
  mode: bps
bps:
  levels: manual
  direction: long_primary
  entry_bps: -9
  exit_bps: -6
  max_entries: 1
  max_position_usd: 1000
```

此时不使用滚动分位数。低位策略必须开仓点位小于平仓点位；高位策略必须开仓点位大于平仓点位。

## 成交和成本

开仓遵循现有主腿成交方式。主腿挂单时，仅将已确认成交量在对冲腿吃单对冲；未成交不发送对冲订单，等待时间仍由 `execution.maker_timeout_sec` 控制。价差离开本轮开仓条件或预计空间不足时撤单。

触发平仓后使用两边 reduce-only 吃单，遵循原有滑点保护和单笔上限；部分成交后继续平剩余仓位，即使溢价随后退回，也不改为反向加仓。小于交易所最小规模但仍超过数量精度的残余仓位会暂停并要求核对；净敞口容差不会把仍可辨认的配对持仓当作空仓。

开仓前估算目标溢价处的退出收益，扣除开仓与平仓手续费、当前盘口价差、盘口深度，以及配置的滑点预算；要求估算值高于 `cost_buffer_bps`。估算假定对冲腿中间价不变、平仓时盘口宽度及费率不变，不保证实际盈利，不包含资金费。平仓按已锁定的溢价点位执行，不用估算盈利值阻止退出。

例如，对冲腿吃单费率若是 2.25 bps，仅该腿开平两次就需 4.5 bps；从 −9 到 −6 的 3 bps 波动不足覆盖这一项成本。原配置的每腿 50 bps 滑点预算也会让小幅波动被成本检查拦截；应按实际执行和风险预算配置，不能为了触发订单忽略真实成本。

该策略没有额外止损或强制最长持仓时间；溢价没有回到平仓点位时继续持仓。停止/暂停程序不会自动平仓。每天 8 点的旧三个套利阈值更新会跳过 bps 策略，不会替换这些点位或重启其持仓周期。

## 重启和日志

日志显示 `[BPS LEVELS]`（来源、窗口及点位）、`[BPS bps_open]`、`[BPS bps_close]`，交易记录的方向带 `bps_open:` 或 `bps_close:`。网页监控摘要显示当前点位、批次和等待/拦截原因。

`logging.file` 对应目录中保存 `.bps-state.json`，包括本轮固定点位、批次和最后已确认的仓位。正常重启只有在交易所仓位与记录一致、市场和账户一致时才恢复。没有归属记录的旧仓位、未完成订单或链上仓位变化会拒绝启动或暂停，不猜测仓位归属，不自动反向平掉旧仓位。未完成状态即使当前仓位为零也需检查交易所未成交订单；确认并处理后才能清理状态文件重启。
