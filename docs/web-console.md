# DEX 套利与监控控制台

控制台直接调用现有 `main.py`，每个任务对应一个独立 Python 进程。两个页面：

- `/dex-arbitrage`：新建、配置、启动、停止多个币种的采集或实盘任务。
- `/monitor`：选择任务，查看双腿盘口、行情新鲜度、持仓、会话估值盈亏、分钟溢价图、成交记录和运行日志。

## 每日 08:00 自动更新阈值

控制台启动后会按 `Asia/Shanghai` 时区每天运行一次自动阈值任务。它在当天
08:00 使用前一天 08:00 到当天 08:00（左闭右开）的分钟数据，扣除当前模式对应的双腿费用，
计算 `midline_bps`、`upper_bps`、`lower_bps`。有效分钟数少于 30、数据文件缺失或
配置校验失败时不会更新，任务详情会显示“今日阈值更新失败”或“待更新”。

实盘任务更新前会先暂停新信号、优雅停止进程并等待当前成交结算；新配置通过校验后
才会原子写入并重新启动任务。启动失败会恢复旧配置。只有更新成功或确认阈值未变化
后，分钟 CSV 才会删除窗口外的旧数据。每个任务的 `auto_threshold.json` 保存当天状态、
旧值、新值、数据窗口和删除行数，事件日志使用完整日期时间，方便确认当天是否已经更新。

默认只采集行情。保存配置不会启动任务；实盘启动需要输入币种确认。运行中的配置必须先停止才能修改。停止后可以直接更换币种、主腿、对冲腿及市场路径：旧运行配置、状态和操作事件保存在 `web-data/<任务ID>/history/<归档ID>/`，归档中的 `outputs.json` 指向原 CSV、日志和 BPS 状态文件，原数据保留。若新旧路径复用同一个输出文件，保存时在原父目录下加入独立的 `route-<ID>/`，实际路径写入 YAML，网页分析和策略运行均读取该配置；原来就不同的路径继续沿用。旧收益、运行时间及当日阈值更新状态重置，不混入新路线。共用 YAML 或只读关联来源在换路线时转为该任务独立配置，避免改掉其他任务的市场。保存切换不撤销旧交易所订单、不平仓，也不自动启动新路线；启动仍核验凭据、仓位与运行冲突。直接在配置库改了关联 YAML 的市场时，需要先打开任务配置保存切换，再启动。自动阈值任务只更新三个阈值并重启任务，不会平仓。

运行中的实盘任务提供「暂停 / 恢复」按钮。暂停只阻止新的套利扫描，行情订阅、账户对账、状态快照和日志继续运行；吃单模式下等待已发订单结算；挂单模式下撤掉当前主腿挂单并对冲最后确认的成交。已有匹配持仓不会自动平仓。恢复只解除人工暂停，行情新鲜度、限频、未对账、保证金和连续错误等风险门仍然有效；如果引擎已经进入 `HALTED`，恢复不会绕过该状态，必须先核对原因后重启任务。只采集任务没有策略下单，因此不显示暂停按钮，只显示「停止」。

任务列表的「阈值」按钮可以手动读取最近一个已完成窗口并预填建议值。你可以直接修改
中线、上带和下带后应用；上带和下带必须大于 0。采集任务应用后从下一次启动读取新值，
实盘任务应用前会优雅停止并重新启动，页面会要求输入币种确认。

点击策略任务的币种或「详情」，无需跳转监控页即可查看运行日志与操作事件。详情每 3 秒刷新，支持自动滚动、手动刷新、下载日志；停止或异常退出后日志仍可读取。未启动的任务会提示暂无日志。运行日志只展示末尾 192 KB，不代表完整历史，完整文件可下载。

## 页面配置库

示例模板随控制台保存在 `web/templates/`，不依赖用户策略目录。删除或编辑 `configs/rh-arcus.yaml`、`config.example.yaml` 不会影响登录或模板加载；模板只用于创建新配置，不会覆盖已有策略或凭据。

DEX 套利页的「配置库」提供两个标签：

- **YAML 策略**：读取项目 `config.yaml` 与 `configs/*.yaml / *.yml`；选择 RH / Arcus 或 Entropy / RH 示例模板，修改后另存为 `configs/<名称>.yaml`。也可以编辑已有文件。文件名只允许 1–40 位字母、数字、下划线或短横线，不接受任意路径或符号链接。保存检查 YAML 结构和基本阈值；具体交易路径、费率与风险参数在保存任务和启动时再次校验。
- **ENV 凭据**：`default` 对应项目 `.env`，其他名称对应 `credentials/<名称>.env`。按交易所模板填写账户、API 索引和密钥，可以保存不完整的草稿；实盘启动时会检查所选凭据是否齐全。已有值仅显示「已配置」，所有值都不回传，留空保留原值，勾选「清除此字段」才删除。服务环境变量覆盖的默认字段会单独提示，必须在服务器移除对应环境变量才能清除。

新建任务时选择「YAML 策略来源」和「服务器凭据配置」。关联 YAML 的任务每次启动读取服务器最新文件，运行期间使用独立快照；修改共享文件不会热更新进程。表单保存会回写关联来源；更换市场路径时，若该来源被其他任务共用，则只将当前任务转为独立配置，保留共用文件。选择「独立配置」则使用任务自己的表单与 YAML。任何运行中任务使用的 YAML 或 ENV 都不能通过配置库覆盖，必须先停止相关任务；停止后的历史任务可直接在配置中保存新市场路径，旧记录会归档。

新保存的 YAML 与 ENV 权限为 `600`；新增的 `configs/*.yaml / *.yml`、凭据及运行数据默认忽略 Git，仓库原有已跟踪的示例文件仍会被跟踪。不要在 YAML 或任务名称中放密钥。新输入的 ENV 值必须经浏览器发送到当前 Python 服务，不能理解成「密钥从不经过浏览器」；已有值不回传，关闭配置库或退出登录会清空输入。请只在本机、SSH 隧道或 HTTPS 下填写，不要在公网明文 HTTP 传输凭据。页面不能修改 `.env.web` 或控制台密码。

## 第一次启动

在服务器项目目录中执行，使用同一个虚拟环境：

```bash
pip install -r requirements.txt
cp .env.web.example .env.web
chmod 600 .env.web
```

编辑 `.env.web`，将 `WEB_PASSWORD` 改为自己的随机长密码（至少 12 位），然后运行：

```bash
python3 web_main.py --host 127.0.0.1 --port 8080
```

此密码是控制台登录密码，交易密钥仍保存在 `.env`。实盘需额外安装 `requirements-live.txt`。访问本机 `http://127.0.0.1:8080/dex-arbitrage`，登录后在页面创建任务。控制台不需要 Node.js、不依赖外部字体或 CDN。

远程访问可以使用 SSH 转发，在自己电脑执行：

```bash
ssh -L 8080:127.0.0.1:8080 root@你的服务器IP
```

随后在自己电脑打开同一地址。也可以通过 HTTPS 反向代理访问。

## 多币种实盘与独立凭据

`.env` 是默认凭据配置。可以在页面配置库创建 `eth`、`btc` 等凭据，也可以在服务器创建 `credentials/eth.env`、`credentials/btc.env` 等文件，字段与 `.env.example` 相同，然后在页面选择对应的凭据名称。不要在 YAML 或任务名称中放入密钥。凭据文件及运行数据已加入 `.gitignore`。

```bash
mkdir -p credentials
chmod 700 credentials
cp .env.example credentials/eth.env
cp .env.example credentials/btc.env
chmod 600 credentials/*.env
```

填写每个文件中的独立 API/agent 密钥。自定义凭据文件独立加载，不会借用其他文件或控制台环境中的交易密钥。默认 `.env` 中的值可以被已设置的同名环境变量覆盖；自定义文件不使用这种覆盖。

采集任务可以共用默认凭据配置并行运行。实盘任务会检查：

- 是否重复运行同币种、同交易所组合（包含反向组合）。
- 是否在不同实盘任务中同时管理同一场所、同一市场的持仓（保守拦截，不按账户放行）。
- 是否共用签名密钥；Lighter 还检查链、账户索引、API key 索引，避免进程各自维护 nonce 造成冲突。

所有同时运行的实盘任务均需使用独立签名密钥。独立子账户更便于隔离保证金和预算。同一主账户的不同 API 密钥仍可能共用保证金、账户权益和账户级限频，页面不会协调这些账户级限制。页面显示的仓位上限合计是各任务配置的双腿上限之和，不是实际持仓；不要将不同币种任务中的账户权益或 account delta 相加。

控制台只管理由它启动的进程，无法识别服务器上手动启动或其他控制台启动的交易进程。切换管理方式前，先停止已有手动实例并核对交易所持仓。不要用不同数据目录同时运行多个控制台管理同一账户。

交换 Arcus 主腿和对冲腿后仍读取同一组 `ARCUS_*`，不会因角色改变选择另一组账户。
只有 `ARCUS_*` 完全未设置时才整组选用 `PRIMARY_ARCUS_*`。实盘启动先校验
Arcus API key 授权和两边旧仓；旧仓不平衡时启动失败，不会自动平仓。

## 停止、故障和历史数据

停止先发送 SIGTERM，沿用引擎的退出机制等待正在执行的套利结算。停止不会自动平仓。任务停止后，再自行核对订单、双腿持仓和净敞口。长时间停止不下来，可在页面单独确认强制结束；SIGKILL 会打断成交确认，必须到交易所核实实际结果。

关闭网页或退出登录不会停止任务。关闭控制台服务会停止其管理的所有任务；退出等待超时后会强制结束子进程。实盘进程检测到控制台父进程退出后，会请求停止。任务实例文件锁防止旧进程还在退出时重复启动同一任务。控制台重启后将之前活跃的记录标为“服务中断”，不会自动恢复实盘交易。

默认不限制同时运行的任务数量（`--max-running 0`）。需要限制时可设置正整数，例如 `--max-running 20`，不再设置 12 或 50 个任务的固定上限。服务器资源和交易所账户限频仍会限制实际承载能力；同市场、同签名密钥和 CSV 路径冲突检查继续生效。

任务配置与控制状态保存在 `web-data/<任务ID>/`，输出文件使用 YAML 配置的路径：

- `config.yaml`：任务配置快照，保留 YAML 的输出路径；相对路径按项目目录解析。
- `status.json`：约每 2 秒更新的引擎状态，不含交易凭据；页面超过 10 秒未更新会标记过期。
- 运行日志：写到 YAML 的 `logging.file`，省略时使用任务目录的 `engine.log`。每次启动都会清空上一轮日志和 `.1`、`.2`、`.3` 编号备份；命令行启动也采用同样规则。
- `events.log`：任务目录中的操作事件；每次启动清空旧事件及其编号备份，重新记录本次 START、暂停、停止和 EXIT。
- 行情和成交 CSV：分别使用 YAML 的 `recorder.csv` 和 `logging.trades_csv`，重启继续追加。BPS 状态文件中的持仓成本也保留。

手动重启、自动阈值更新引发的重启都会删除上一轮文本日志。需要分析上一轮时，请先下载；停止任务时仍保留本次日志，直到下一次启动。暂停／恢复不会清空。运行任务不能共用 `logging.file`，避免清空或混合彼此的日志。

监控页行情图展示最近 120 条分钟记录，不是逐笔实时图；日志显示末尾 192 KB。行情需要双腿有效盘口才会形成分钟记录。采集模式不查询持仓，持仓与盈亏显示为空值。会话 MTM 是根据盘口估值的会话变化，不等于已实现收益。停止后的快照会明确标记为非实时。

CSV 不自动删除，需按磁盘容量自行备份、归档。页面删除任务只移除任务记录，保留服务器历史文件。

成交记录中的“匹配成交净价差”不是交易所的平仓已实现盈亏，而是本次双腿匹配数量的卖出金额减买入金额及配置手续费。金额展示四位小数；只有单腿成交、未成交或缺少实际成交均价时显示 `—`，不把无法计算的价差当作零亏损。手续费按 YAML 费率估算，旧 CSV 缺少金额字段时也显示 `—`。交易统计的已实现盈亏按本次运行内每个交易所分别 FIFO 配对，无法确认旧仓成本时不提供确定值；不包含资金费，不能直接作为交易所完整账户账单。核对时需保持币种、账户及时间范围一致，分别比较两边平仓盈亏与手续费，再单列资金费。

账户权益独立于盘口状态：行情“正常”不代表余额已读取。实盘每约 30 秒读取账户权益与可用金额，页面分别显示首次等待读取、读取失败、最后成功时间和过期状态；首次失败显示 `—`，后续失败保留旧值并注明非实时，不伪造零余额。Arcus 同时显示所选主网/测试网和子账户编号，不展示地址、签名或私钥。接口确认返回零时保留真实零值并提示核对账户范围，不会擅自切换子账户。没有实际成交时，本次运行成交额和手续费为零是正常现象；挂单委托额不是成交额。

### 多市场价差监控

监控页的“市场价差”面板读取 RH Lighter、Arcus 和 Entropy 的公开市场列表，显示任意两个市场共有的活跃币种。例如 BTC 只有 RH 与 Arcus 支持，也会显示 RH↔Arcus 的价差，不需要 Entropy 同时上市。监控列表不按数量步长、最小下单数量、正负价差或策略阈值筛选；只有单市场支持的币种无法计算跨市场价差，不列入监控。

点击“监控全部币种”后，页面订阅每个币种可用市场的公开订单簿，在总表中显示 RH↔Entropy、RH↔Arcus、Arcus↔Entropy 的中间价差和双方向可成交价差。缺失市场、行情未就绪或心跳过期的组合显示 `—`；一个市场列表或盘口连接失败时，其余两个有效市场仍可监控。启动时最多并发连接四个币种，全部监控会增加网络连接和服务器资源消耗，交易所限流或连接失败会显示错误。可选策略 YAML 只提供费率，不是启动条件，阈值不参与监控。价差不等于利润，行情展示不能证明合约规格适配，实盘前仍需核对手续费、滑点及合约乘数。

在页面顶部点击「Telegram 通知」，在 ENV 凭据中填写 `TELEGRAM_BOT_TOKEN` 与 `TELEGRAM_CHAT_ID`，保存后点击「发送 Telegram 测试」确认 Bot 能实际发到目标会话。每个任务使用自己选择的凭据配置；如果任务选择了 `credentials/*.env`，Telegram 字段也要填在该配置里。市场监控在数量步长和最小数量可验证的 RH 主腿路径出现扣费后为正的可成交价差时发送 Telegram 通知，同一方向 60 秒内不会重复发送；行情展示不受该通知条件限制。

每次实盘主成交和后续补对冲都会发送一条通知，包含本次成交额、本次已实现价差收益、两边合计累计成交额、累计已实现价差收益、对冲笔数，以及每个交易所的可用余额和账户权益；如果引擎已取得基准，还会附上账户权益变化。累计收益采用成交价差减双腿吃单费计算，不包含未实现盈亏。没有这两个字段时，监控和交易都不会因为通知失败而停止。

采集子进程不注入交易凭据；只有实盘进程接收所选配置的凭据。控制台管理的子进程日志在写入磁盘前，会遮蔽已加载的私钥、签名密钥、账户地址及常见认证字段；跨读取块的密钥也会处理。单行超过 64 KB 时整行省略，避免无限缓冲及部分泄露。此过滤只覆盖控制台新捕获的日志，不修改以前的日志或手动命令启动的输出，也不能保证识别第三方库所有未知的编码方式。前端没有第三方统计脚本、远程字体或外部 CDN；监控中的交易与持仓数据仍属于敏感信息，只有登录后才能读取。

`.gitignore` 防止这些文件被普通 Git 提交，但不是加密或服务器访问控制。服务器管理员、同一系统用户或入侵者仍可能读取凭据文件和交易进程内存/环境。部署目录不能被 Nginx/宝塔作为静态根目录公开；只代理到 Python 服务。请使用独立 API/agent 密钥、限制授权范围，并配置文件权限、HTTPS 或 SSH 转发。

## 常驻 Linux：systemd

只需配置一次常驻服务，之后单个币种的操作都在页面完成。示例路径与你当前服务器目录一致，但请按实际虚拟环境位置修改；可以使用具备目录权限的专用系统用户。

```ini
[Unit]
Description=Entropy DEX web console
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/www/wwwroot/code/entropy-arb
ExecStart=/www/wwwroot/code/entropy-arb/.venv/bin/python web_main.py --host 127.0.0.1 --port 8080
Restart=on-failure
RestartSec=5
KillMode=mixed
TimeoutStopSec=120
UMask=0077

[Install]
WantedBy=multi-user.target
```

保存为 `/etc/systemd/system/entropy-web.service`：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now entropy-web
sudo systemctl status entropy-web
```

`Restart=on-failure` 只恢复控制台服务，不恢复交易任务。systemd 超时会终止剩余进程，未结算订单和持仓仍需人工核对。部署更新前先停止页面上的交易任务。

## HTTPS 反向代理

推荐将 Python 只监听 `127.0.0.1`，由 Nginx/宝塔站点配置 HTTPS 和以下反代位置：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
}
```

HTTPS 部署时，在启动命令加入 `--secure-cookie`。Python 不信任客户端的转发头；代理必须保留原始 Host，才能通过页面操作的来源检查。密码失败限频按 Python 接收到的连接地址执行，经过代理时可能共用这一限频。

不推荐直接暴露明文 HTTP 到公网。确需内网访问可用 `--host 0.0.0.0` 并限制防火墙来源。登录会话持续 12 小时，重启控制台会失效。控制台密码和 HTTPS 证书需要在服务器配置；页面配置库可以新增或更新交易凭据，但不能修改控制台密码。

主腿可选择吃单或 Post-only 挂单，等待时间可配置；详细成交、撤单与手续费规则见 [主腿成交方式](primary.md#主腿吃单--挂单)。

Arcus 为主腿且选择挂单时，开仓、平仓和 Arcus 余仓修正均只发送 ALO，不自动转吃单；平仓和修正同时带只减仓限制。另一腿仅按 Arcus 已确认的平仓成交量吃单减仓，Arcus 修正不向另一腿发单。页面监控显示该限制，并按实际 maker 费率估算 Arcus 费用。挂单不保证成交，止损、超时退出或纠偏可能等待，未确认订单继续阻止新单。其它交易所和明确配置的 taker 任务不受此规则影响；升级不会自动启动或重启实盘任务。

Arcus 主腿挂单 + RH 对冲时，开仓、平仓挂单量按 RH 滑点范围内可对冲深度乘 YAML 的 `sizing.take_fraction` 自动限制，与原策略其他规模限制取更严格者；没有最低规模的承接量就不挂单。下单前重新检查，挂单期间深度不足则撤单重算，不改变策略点位、金额上限或 Arcus 只挂单约束。`[MAKER SIZE]` 日志显示实际挂单量、RH 深度与容量。

RH 已确认成交对冲使用 YAML 的 `execution.hedge_slippage_bps`，不被原 BPS 入场余量压缩；RH 回执明确因滑点取消、零成交且结果已确认时，不设补单次数上限，每次按最新盘口及配置滑点重算保护价，不固定首次价格。每次补单前重新检查最新行情、深度及下单预算；未知订单不重发，也不把部分成交当零成交补发全量。暂停/停止、行情不可用、预算耗尽、限流或其他执行问题仍停止补单，按原有剩余敞口恢复或暂停规则处理。持续跟随盘口可能扩大磨损，不保证对冲成交。运行日志的 `[MAKER-HEDGE SEND]` / `[MAKER-HEDGE RESULT]` 显示每次保护价和成交回执。


## BPS 完整往返净收益试运行模式

现有任务默认保留固定点位模式。要试用新版，在“溢价 bps 开平仓”的“平仓规则”中选择“完整往返净收益止盈 / 止损”，保存并重新启动任务；或选择配置库中的 `bps-profit-rh-lighter.yaml`。该示例用于 RH 主腿、Lighter 对冲，手续费需按实际账户核对，参数不保证盈利。

新版开仓仍使用 YAML 的 recorder.csv 中滚动分位数，但要求这笔订单的真实盘口报价也达到开仓点位，参考回归跨度至少达到 min_gap_bps，并覆盖当前同规模往返盘口成本、四腿配置手续费、滑点预留及 cost_buffer_bps。这些只是当前盘口保护，不预测将来价格。买卖价差很小的市场可能没有合格开仓机会。

本轮记录双腿实际成交现金流（包含加仓、部分平仓、纠偏成交及配置手续费）。止盈、止损比较“这轮现金流 + 全部剩余仓位按当前深度退出的保守现金流”，使用最差盘口档位、价格取整及每腿滑点预算；分母为主腿这轮累计开仓成交额，不是双腿成交量。300美元主腿开仓额的1bps为0.03美元。参考回归点位用于开仓空间检查，净收益模式不再仅因为中间价到达该点就平仓。

试运行示例：take_profit_bps=1，stop_loss_bps=10，max_hold_sec=900，min_gap_bps=2，entry_confirm_sec=2，cycle_cooldown_sec=30，add_step_bps=0.5，execution_slippage_bps=1，cost_buffer_bps=0.5。止损、最长持仓设0可关闭；其它阈值均可配置。执行滑点取 execution.leg_slippage_bps 与 bps.execution_slippage_bps 中较小值；挂单后的对冲也受较小滑点预算约束。

持仓时间从首次实际成交开始，加仓不会延长时限。首次触发退出后保持分批只减仓，后续行情变化可能使最终净收益低于止盈目标或超过止损额度；缺少退出深度时等待深度，无法保证在期限内成交。完全平仓后冷却，冷却状态与成本均保存在 .bps-state.json。配置费率未覆盖交易所实际额外收费或资金费时，净收益也不会包含这些未提供的成本。

新版成本记录可以跨重启恢复，正常会话成交额、手续费与已实现收益统计仍按本次启动计算。历史状态没有成本或直接接管旧仓时，成本标记为未知，不把未知当0：停止继续加仓，按原BPS平仓点或最长持仓退出。仍拒绝未确认订单或与状态记录不符的仓位。手动暂停、风险暂停或停止程序会停止自动扫描，已有仓位不会自动平仓。

监控中的“保守退出净收益”是当前报价计算值，不是已实现利润。每轮实际完全平仓后写入 [BPS CYCLE] complete，记录实际已确认成交的轮次净值；成交记录的单笔字段显示为“成交净价差”，与完整往返净收益分开。


## 实际可成交价差交易

在任务“交易策略”选择“实际可成交价差（双向、不限批次）”，将交易价差门槛设为 1 bps。
配置为 `strategy.mode: spread`、`strategy.spread_bps: 1.0`。
两个方向都按买入方卖盘、卖出方买盘逐档计算 `(卖出价 / 买入价 - 1) × 10000`，只有严格大于门槛的深度可以下单。
不读取中位数或分位数，不等待 120 分钟数据，不设开仓批次上限，不使用整轮净收益目标，也不应用每日自动阈值。
单笔金额、每腿持仓上限、最小下单量、行情连接状态、限频和滑点保护继续生效。
这个模式使用吃单；发送前按最新盘口和剩余仓位空间重算数量。
已有仓位不会因停止或切换模式而自动平仓，反向可成交价差达标时可以减少原有仓位。

这里的门槛是扣手续费前的价格差，手续费仍按 YAML 计入预计与实际成交收益。
因此 1 bps 价差不代表盈利；费率与滑点可能使实际收益为负。
已有任务需停止后切换策略并保存，再自行启动；更新代码不会自动修改运行中的策略。

BPS 点位模式和净收益模式均已取消最多开仓批次，旧 YAML 的 `bps.max_entries` 不再生效，无需手动修改旧值。仍按单笔下单上限、每腿仓位上限和 `bps.max_position_usd` 控制规模，加仓仍遵守 `bps.add_interval_sec`。本轮实际成交批次仅用于统计和持仓状态恢复，不作为交易限制。已有任务升级后须重启才能使用新逻辑。

BPS 自动点位默认使用“最近 N 条有效记录（可跨时段）”：历史超过 120 条就直接取最新 120 条有效分钟记录，不要求连续，也不要求本次启动后采集。页面显示最新参考历史起止时间及最后记录距今多久。需要最近 120 分钟的严格时间范围时，可选择“最近 N 分钟时间范围”。`bps.history_mode` 分别为 `records`（默认）和 `time`；`window_minutes` 在记录模式下表示记录条数。已有持仓的点位继续锁定，更新的历史供下一轮参考。


BPS 的“价差口径”选择“可成交价差（买卖报价）”时，使用主腿/对冲腿的买一卖一，适用于任意交易所组合。买主腿方向：开仓为对冲腿买一 / 主腿卖一，平仓为主腿买一 / 对冲腿卖一，均减 1 后乘 10,000，均须 ≥ 各自点位；反向持仓交换开平方向。历史复用 CSV 的四个买卖报价列重算两条独立分位数曲线，实时数量只取达标深度。开仓遵循主腿 maker/taker 配置；Arcus 主腿 maker 配置的平仓及 Arcus 纠偏也只挂单，另一腿按已确认成交量吃单对冲；手续费另计，不增加最低盈利条件。旧滚动配置的低位尾部会转换到新高价差尾部（如 10/75 → 90/75），显式保存后不再转换。旧手动配置和净收益模式保留兼容口径，手动切换时重新填写两个独立点位。已有配对仓位可在核验无挂单及仓位稳定后直接切换当前 BPS 口径，点位重新计算，不需先清仓，也可按新点位和持仓限制加仓。新网页字段需要重启网页服务加载；服务重启会影响其托管的运行任务，停止程序不会自动平仓。

不同币种实盘任务共用签名密钥时允许启动，仅显示提示，并记录在操作事件中。提示包含可能的 nonce 冲突及限流风险，不暴露密钥或指纹。同一市场的重复实盘管理及共享行情/日志文件仍拦截。

## RH / Lighter 公开账户监控

页面顶部增加「按钱包地址对比 RH / 主网开平仓」：输入完整钱包地址、选择分析窗口，
点击「查询地址并分析」。即使连续采集已停止，也可查询两边的公开地址目录并分析本地已采集历史。
当前并不自动导入私有账户历史、浏览器日志或付费全量历史，缺少记录时会明确提示，不能凭地址复原所有过去交易。
普通账户历史成交接口需要授权；参考[官方 trades 说明](https://apidocs.lighter.xyz/reference/trades)。

结果按「完整双腿往返」展示 RH / Lighter 主网的开仓对比、平仓对比，
并可展开本轮加仓、减仓的全部已匹配成交。只有两边均从可确认的零仓位开始、最终归零、
仓位连续且未跨过已记录缺口、无遗漏的未匹配成交，才计为完整往返。
仅有开仓或平仓片段时仍展示双边成交，不伪造一轮完整交易。

交易特征分析基于实际样本计算常见方向、开平仓成交价溢价中位数、持有时长、加仓轮数、
价差收敛比例与 Maker/Taker 成交金额占比。少于三轮完整样本不作策略类型判断。
成交先后不证明程序下单顺序，样本价差不等于真实触发阈值，分析不能证明净盈利。
两边分别最多取最近 2,000 笔作为匹配样本，并显示截取提示；完整往返、成交片段最多各显示 50 组。

账户榜新增「对冲识别 / 对边」，区分待查询、对边查询失败、未查到同地址账户、
对边未采集到成交、双边有成交但未匹配、已观察到疑似配对等状态。
后台逐步核验对边地址目录，列表证据摘要最多缓存约 15 秒；打开钱包分析可重新查询。
没有匹配证据不等于该地址没有在其他钱包或平台对冲。

侧栏的「账户监控」（`/accounts`）独立于策略任务，使用公开查询接口和只读 WebSocket，
不加载交易凭据，不发送订单，不修改现有策略的开平仓规则。

1. 输入币种，例如 `BTC,ETH,SPY,QQQ`；`*` 监控两边全部活跃、单位乘数为 1 的永续市场。
   币种可以只在一边上市，这种情况下可以统计账户成交，但没有双边 bps。
2. 可勾选「补充每市场最近最多 100 笔成交」。这是有限的近期数据，不是完整历史；
   实时流与补充数据按「平台、市场、成交编号」去重。未勾选则从启动后订阅到的数据开始累计。
3. 点击「启动 / 更换币种」，逐步建立成交与最优买卖报价订阅。
   切换币种或停止采集均保留旧数据；统计范围仍包含旧币种已采集的数据。
4. 按近 1 小时、24 小时、7 天或全部已采集数据查看活跃账户排名。账户编号按平台区分。
   账户买卖成交都计入该账户成交额；撮合成交额只计一次，不能把双方账户成交额当市场成交额。
5. 点击账户「详情」，或直接添加已知账户编号。「查询最新仓位与关联」获取公开仓位快照，
   并在另一平台查询同一公开地址的账户。关注账户在采集运行时优先定期刷新，
   未关注账户仅逐步补充公开信息；历史成交筛选不会改变当前仓位快照。

同地址、同币种、方向相反、时间相差不超过 3 秒且基础数量相差不超过 5% 的成交，
会作为一对一的疑似对冲候选展示，不重复使用同一笔对边成交。
这不是身份验证，也不是策略确认：不同钱包、拆单、跨其他平台对冲会漏配，偶合可能误配。
双边成交价 bps 只是两笔成交价格之比，不代表同步可成交机会或净利润。

每组疑似对冲按两条成交分别展示：平台、账户、上海时间（含毫秒）、买卖方向、
Maker/Taker、实际成交价格、数量、成交额、市场和成交编号，保留两边不同的实际数量。
开多、加多、减空、平空等标记按公开成交前仓位变化推算，缺少该字段时显示「开平未知」。
组内成交额为两笔成交额之和，不作为利润。详情还展示同地址关联对边的最近 100 笔已采集成交，
即使没有满足时间/数量匹配条件也能查看；不会把未匹配成交强行当成对冲。

成交时中间价 bps 固定为 `(RH mid / Lighter mid - 1) * 10000`，
只使用截至成交时间、已收到且距该成交不超过 3 秒的两边报价；缺少、过期或只有未来报价时显示 `—`。
近期成交补充通常没有对应的历史报价，不使用之后的行情补算。两边报价币 USDG / USDC 未作汇率换算。

详情只对所选窗口最近 2,000 笔做行为与往返分析，成交明细展示最近 100 笔，超过时明确标注截取。
只有成交前仓位可确认从 0 开始、回到 0、且没有跨过已记录的数据缺口的交易序列，
才列为「完整单平台往返」。成交现金差未扣手续费、资金费，不能当成跨平台策略净收益。
缺少成本、缺单或无法关联对边时，不伪造净利润。行为标签只是样本内的可观察特征。

数据保存在 `--data-dir` 下的 `accounts.sqlite3`（SQLite WAL），不会写入策略的分钟 CSV。
关闭浏览器继续采集；重启控制台时恢复此前已启用的监控；点击「停止采集」会取消下次自动恢复。
数据不会自动清理，可在停止控制台后备份整个数据目录（运行中备份须使用 SQLite 备份机制）。
数据库写入和统计查询在线程中执行，读连接与写连接分开，避免阻塞网页事件循环。

每个平台公开 REST 查询至少间隔 4 秒，遇到限流退避 60 秒；WebSocket 订阅逐步发送，
分组连接并带重连与心跳。断线、队列溢出、无效记录会留下采集事件；重连不保证补齐缺口。
这只是监控自身的限速，不是全服务器限速协调，仍可能与实盘共享 IP 配额。
